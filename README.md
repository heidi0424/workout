# 訓練菜單與動態追蹤系統

GitHub 專案：https://github.com/heidi0424/workout

## 公司與家裡怎麼接著做

GitHub 存放兩台電腦共用的程式碼和交接文件。公司和家裡都已將專案放在 `D:\HeidiSite\workout`。

### 設定 Codex 專案資料夾

在 Codex 新增本機專案，選取 `D:\HeidiSite\workout`。如果已經有 workout 專案，開啟專案選單的「編輯專案」，將該資料夾設為主要資料夾。之後在 workout 專案中開始工作。

如果要在另一台電腦安裝，先檢查是否已經有 workout 檔案。空白路徑可從 GitHub 複製到空資料夾，再將該資料夾加入 Codex。沒有 D 槽時可使用 `C:\HeidiSite\workout`。

### 每次只要記得兩句話

- 開始前：「開始工作，先更新並讀取進度。」
- 結束前：「收工同步，更新進度並上傳 GitHub，確認上傳成功。」

開始修改前，Codex 會先檢查本機尚未上傳的內容，再取得並整合 GitHub 最新版本、讀取進度。請等上一台電腦上傳成功，再到另一台開始修改。

### 家裡已經有修改時

不要重新下載覆蓋家裡原本的資料夾，也不要刪除尚未上傳的檔案。

在家裡原本修改此專案的 Codex 專案中說：「請先檢查並保留這台電腦的修改，整合 GitHub 最新版本，再把家裡的修改上傳；不要覆蓋任何一邊的內容。」

如果原本是下載 ZIP 而沒有 Git 紀錄，請先另外複製一份備份，再由 Codex 比對家裡版本與 GitHub 版本，將確認要保留的修改整合到 Git 專案，不能直接用其中一邊覆蓋整個資料夾。

家裡確認上傳成功後，公司這台再說「開始工作，先更新並讀取進度」，即可取得家裡的修改。

## 進度怎麼接續

新的聊天先讀 `PROGRESS.md`，就能了解上次做了什麼和下一步。此文件不代表完整聊天紀錄。

## 網站檔案

- `index.html`：網頁與樣式。
- `app.js`：網站功能與資料同步。
- `api/photos.mjs`：私人照片 API。
- `vercel.json`：部署設定。

開啟 HTML 只能查看部分前端效果。私人照片與 Google 登入依賴部署環境設定，不會因下載程式碼就自動完成設定。

GitHub 不會同步瀏覽器中尚未送出的訓練資料、照片、登入狀態或本機聊天紀錄。請勿把環境變數、密碼或私人資料加入版本控制。
