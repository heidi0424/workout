# 訓練菜單與動態追蹤系統

GitHub 專案：https://github.com/heidi0424/workout

## 公司與家裡怎麼接著做

GitHub 存放大家共用的最新程式碼。這台電腦的專案資料夾是 `D:\HeidiSite\workout`。`D:\HeidiSite` 是放置各專案的上層資料夾。

### 這台電腦

在 Codex 新增或開啟專案，選取 `D:\HeidiSite\workout`。之後在這個專案的聊天中提出修改需求。

### 家裡電腦第一次使用

1. 安裝 Git 和 Codex，並登入你的帳號。
2. 建立一個放專案的上層資料夾，例如 `D:\HeidiSite`；若沒有 D 槽，可用 `C:\HeidiSite`。
3. 在 Codex 新增專案並選取該資料夾。
4. 對 Codex 說：「請將 https://github.com/heidi0424/workout 複製到目前資料夾下一層的 workout 資料夾。若已有檔案，先檢查，不要覆蓋。下載後請讀取 workout 裡的 AGENTS.md 和 PROGRESS.md。」之後將 Codex 專案資料夾選為 `D:\HeidiSite\workout`（或實際使用的路徑）。
5. 第一次上傳時如果需要 GitHub 登入，依提示登入有寫入此專案權限的 GitHub 帳號。

### 每次只要記得兩句話

- 開始前：「開始工作，先更新並讀取進度。」
- 結束前：「收工同步，更新進度並上傳 GitHub，確認上傳成功。」

請等上一台電腦上傳成功，再到另一台開始修改，避免兩邊改到同一個檔案。

### 家裡已經有修改時

不要重新下載覆蓋家裡原本的資料夾，也不要刪除尚未上傳的檔案。

在家裡原本修改此專案的 Codex 專案中說：「請先檢查並保留這台電腦的修改，整合 GitHub 最新版本，再把家裡的修改上傳；不要覆蓋任何一邊的內容。」

如果原本是下載 ZIP 而沒有 Git 紀錄，請先另外複製一份備份，再由 Codex 比對家裡版本與 GitHub 版本，將確認要保留的修改整合到 Git 專案，不能直接用其中一邊覆蓋整個資料夾。

家裡確認上傳成功後，公司這台再說「開始工作，先更新並讀取進度」，即可取得家裡的修改。

## 進度怎麼接續

新的聊天先讀 `PROGRESS.md`，就能了解上次做了什麼和下一步。此文件不代表完整聊天紀錄。

## 網站檔案

- `index.html`：網頁與樣式。
- `app.js`：網站功能與資料同步。
- `api/photos.mjs`：私人照片 API。
- `vercel.json`：部署設定。

開啟 HTML 只能查看部分前端效果。私人照片與 Google 登入依賴部署環境設定，不會因下載程式碼就自動完成設定。

GitHub 不會同步瀏覽器中尚未送出的訓練資料、照片、登入狀態或本機聊天紀錄。請勿把環境變數、密碼或私人資料加入版本控制。
