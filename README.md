# 訓練菜單與動態追蹤系統

GitHub 專案：https://github.com/heidi0424/workout

## 公司與家裡用對話接著修改

預設在同一段 workout 固定雲端對話中，透過 GitHub 連接工具直接接續 main 分支。公司與家裡登入同一帳號後，直接描述想要的功能或問題即可，不需下載、clone 或建立本機專案。下方本機流程只供日後明確選擇本機工作時參考。

兩台皆需能存取同一個 GitHub 儲存庫。只登入同一個 Codex 帳號，不代表 GitHub 連接與寫入權限已完成，首次使用需確認。

## 在本機 workout 資料夾接續

1. 在 Codex 的側欄開啟「專案」，新增本機專案，選取 `D:\HeidiSite\workout`。沒有 D 槽時可使用 `C:\HeidiSite\workout`。
2. 如果已有 workout 專案，從專案選單選「編輯專案」，加入正確資料夾並設為主要資料夾。
3. 要修改時，說「開始工作，先更新並讀取進度」。Codex 會先檢查本機未上傳的變更，再取得並整合 GitHub 最新版本，讀取進度。
4. 換電腦前說「收工同步」。等進度更新、變更上傳，並確認本機與 GitHub 一致後，再換到另一台。

## 左側專案與 GitHub

左側的專案用來整理 workout 相關聊天與專案指示。GitHub 則存放程式碼、操作規則與進度。建立或開啟左側專案，不等於已讀取 GitHub 最新版本。

只透過 GitHub 工作時，若目前介面支援不附加資料夾的專案，可建立名為 workout 的專案，不附加本機程式碼資料夾，將下方啟動指示放入專案指示。若版本僅支援選取本機資料夾，不要因此重新下載網站；也可先使用固定聊天或側欄自訂區段整理，並貼上同一段指示。

## 透過 GitHub 工作時的專案指示

這是 workout 固定雲端工作對話。每次使用者傳送訊息時，預設接續 https://github.com/heidi0424/workout 的 main 分支，自動先確認最新完整 SHA，並從該版本讀取 AGENTS.md、PROGRESS.md、README.md 及相關檔案，不需使用者說「開始 workout」。直接透過 GitHub 工作，不下載、clone 或使用本機副本，不另建聊天。沒有修改需求時只讀取、不修改。有明確修改需求時，完成適當驗證、自動更新 PROGRESS.md；寫入前重查分支並整合其他更新，以 expected_sha 或等效檢查避免覆蓋，不強制推送。儲存後重新核對提交及檔案並提供提交連結，不需另外說「收工同步」。需求不清楚或衝突無法判斷時再詢問；無法存取或儲存時明確告知，不把未驗證的功能或部署說成完成。

GitHub 文件不會自動更改 ChatGPT 的專案固定指示；新對話仍需由專案固定指示引導讀取上述規則。同一段已接受這項要求的對話依此接續。

## 透過 GitHub 工作時怎麼說

直接說需求，例如「訓練紀錄新增備註欄位」或「幫我看看照片為什麼無法顯示」。版本確認、相關檔案讀取，以及修改後的進度更新和儲存由助理主動完成，不需啟動或收工口令。

每次傳送訊息才執行版本確認；單純開啟對話不會觸發檢查。公司與家裡使用同一段對話，上一項修改確認 GitHub 儲存成功後即可換電腦接續。

## 若家裡有尚未儲存的修改

先找出原本聊天或檔案，讓 Codex 保留並比對 GitHub 最新版本後整合。只存在另一台電腦的內容，不會因為切換為 GitHub 工作方式就自動出現。不要直接以遠端版本覆蓋尚未保存的內容。

## 網站檔案與驗證

- index.html：網頁與樣式。
- app.js：網站互動及資料同步。
- api/photos.mjs：私人照片 API。
- vercel.json：部署設定。
- AGENTS.md：操作規則。
- PROGRESS.md：跨電腦交接進度。

私人照片與 Google 登入需要部署環境設定。GitHub 儲存成功不等於網站部署已完成，也不等於功能測試通過。聊天紀錄、瀏覽器登入及尚未送出的訓練資料不會隨程式碼同步。
