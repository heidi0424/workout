# 訓練菜單與動態追蹤系統

GitHub 專案：https://github.com/heidi0424/workout

## 公司與家裡用對話接著修改

兩台電腦都請 Codex 透過 GitHub 連接工具直接讀取與修改這個專案。GitHub 是共用的程式碼儲存位置，不必下載、建立本機 Git 專案，也不必設定相同路徑。

兩台皆需能存取同一個 GitHub 儲存庫。只登入同一個 Codex 帳號，不代表 GitHub 連接與寫入權限已完成，首次使用需確認。

## 左側專案與 GitHub

左側的專案用來整理 workout 相關聊天與專案指示。GitHub 則存放程式碼、操作規則與進度。建立或開啟左側專案，不等於已讀取 GitHub 最新版本。

若目前介面支援不附加資料夾的專案，可建立名為 workout 的專案，不附加本機程式碼資料夾，將下方啟動指示放入專案指示。若版本僅支援選取本機資料夾，不要因此重新下載網站；也可先使用固定聊天或側欄自訂區段整理，並貼上同一段指示。

## 專案指示／新聊天啟動指示

請直接透過 GitHub 操作 https://github.com/heidi0424/workout ，預設使用 main 分支，不以本機副本為依據，也不要求下載。每次開始新的修改任務前，先確認 GitHub 最新提交，再從該版本讀取 AGENTS.md、PROGRESS.md 和相關檔案，按規則接續。完成修改後更新進度、檢查版本是否被另一台更新、整合後儲存至 GitHub，並核對儲存成功。無法連接或寫入時請明確告知。

遠端 AGENTS.md 不保證會被新聊天自動讀取，因此需把以上指示放入專案指示，或在新聊天開始時貼上。

## 每次怎麼說

- 開始：「開始 workout，先確認 GitHub 最新版本、讀取規則和進度，再告訴我上次做到哪裡。」
- 修改：「請依 GitHub 最新版本幫我修改……，完成後更新進度並存回 GitHub。」
- 收工：「收工同步，確認本次修改和進度已存回 GitHub，給我提交連結。」

單純打開 Codex 不會自動確認版本。每次交代開始或修改時才執行確認；兩台都遵循同樣規則。上一台確認儲存成功後，再到另一台接續。

## 若家裡有尚未儲存的修改

先找出原本聊天或檔案，讓 Codex 保留並比對 GitHub 最新版本後整合。只存在另一台電腦的內容，不會因為切換為 GitHub 工作方式就自動出現。不要直接以遠端版本覆蓋尚未保存的內容。

## 網站檔案與驗證

- index.html：網頁與樣式。
- app.js：網站互動及資料同步。
- api/photos.mjs：私人照片 API。
- vercel.json：部署設定。
- AGENTS.md：操作規則。
- PROGRESS.md：跨電腦交接進度。

私人照片與 Google 登入需要部署環境設定。GitHub 儲存成功不等於網站部署已完成，也不等於功能測試通過。聊天紀錄、瀏覽器登入及尚未送出的訓練資料不會隨程式碼同步。
